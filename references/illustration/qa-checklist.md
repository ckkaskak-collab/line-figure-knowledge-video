# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 角色与项目选定参考图及身份记录一致。默认参考为 `assets/character/reference.jpg`，其特征是蓬松发型、竖线眼、大头短身、宽袖宽裤、黑线白色留空；自有角色按自己的身份特征检查。
- 新生成图调用确实传入了用户角色参考图。
- 线稿小人承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

下列五官、发型和衣裤举例针对默认角色；自有角色以项目参考为准。

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 角色被画成实心黑色、白点眼、火柴腿，或发型衣裤偏离原图。
- 额外增加腮红、闪亮眼、夸张嘴巴等表情包处理。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 复刻已做过的案例构图，没有为当前文案重新设计。

## 迭代方法

- 太普通：让线稿小人成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 额外萌化或角色漂移：重新引用用户原图，保持原图比例与五官；减少表情和装饰。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和线稿小人动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。
