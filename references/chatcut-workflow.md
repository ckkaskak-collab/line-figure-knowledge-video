# ChatCut 剪辑 2.0 工作流接口

这是用户指定的流程接入说明，不改写[飞书 ChatCut 2.0 原文](original-prompts/feishu/chatcut-editing-v2.txt)。开始该阶段时，完整读取原文，再另附本页涉及的用户选择与实际项目输入。

## 工作流位置

定稿 → 配音与声学对齐 → 飞书视觉编排 2.0（九列表与节拍点） → ChatCut 剪辑 2.0 → 可编辑工程与制作清单。

ChatCut 阶段内部按原文组织 A-roll、B-roll、字幕、音效与 BGM。包内角色接口是其中的 A-roll 图片生成入口，B-roll 动效沿用 X 06 的选择方法。已做好且符合当前分镜的素材直接复用；缺少的图片可在这一阶段调用 Ian 补齐，不强制在建工程之前重做所有素材。

B-roll 已采用[浅灰手绘视觉规范](broll-visual-style.md)。维护 Skill 或比较新候选风格不启动整片剪辑。后续一旦用户授权整片制作，按已确定方案连续完成，不逐镜重复请求确认。

## 阶段交接

沿用已有项目文件，交接时标明下面这些输入的实际位置；不为凑齐清单复制一套资料。

| 输入 | 如何接入 |
|---|---|
| 定稿、配音和声学时间轴 | 原文件保留；真实发声记录与连续编排表分开，按[时间与项目交接](timing-and-handoff.md)接入，不自动重新配音或变速 |
| 九列表与两种节拍点列表 | 来自本次视觉编排，镜头编号与结束值逐项对应；ChatCut 不重新规划切点 |
| A-roll 素材与镜头对应关系 | 已有图片按镜头及状态号导入，并携带动作短语与时点；未生成的镜头交给 [角色接口](aroll-ian.md) |
| B-roll 设计规范 | 读取[已确认规范与参考图](broll-visual-style.md)，将配色、手绘线条、文字气质和留白写入项目预设；具体字体文件按实际环境确定 |
| 真实截图、录屏与数据材料 | 对应到使用它们的镜头；缺少时沿用原文的缺素材处理，不生成假证据 |
| 目标工程与成片规格 | 新项目按本次需求建立，继续项目则使用指定工程；读取实际尺寸和帧率 |

## 用户选择，单独附在原文之外

**A-roll 使用内置角色接口。** 原文第三步仍保留，实际生成时读取本包 `aroll-ian.md` 和 `illustration/` 参考。角色基准是本包原图或项目明确指定的原图，场景和笔触遵守对应参考规则。没有三视图、场景图或细节图时，不虚构这三种文件；明确告知本项目用 Ian 的参考与已生成画面替代原路线。已有合格图片直接导入，不在 ChatCut 内再换一种角色重生成。

**B-roll 沿用已确认的浅灰手绘。** 原文包含没有预设时自行提取规范并继续制作的规则。本项目已有用户确认的[规范与参考图](broll-visual-style.md)，即使目标 ChatCut 工程尚无预设，也应把这套规范落实到工程，而不是重新决定风格。用户明确要求变更时再按本次范围调整。

**A-roll 采用关键状态图切换。** 按 [Ian 动作接口](aroll-ian.md)生成必要状态，逐一对应旁白；可作少量推近，但不能用缩放替代分镜里的行动。

**B-roll 与时间交接。** 按[元素与动作接口](broll-editable.md)从已确定布局制作可编辑元素；按[时间接口](timing-and-handoff.md)分别保留真实发声、连续切镜和镜头内部动作。新增说明不改动原文文件、标点或校验基准。

## 实际执行

1. **接入工程。** 实际开始剪辑时读取当前可用的 ChatCut 基础 Skill；创建或指定本次工程，并返回工具给出的编辑器链接。按宿主实际提供的 hosted plugin 或桌面端工具使用对应指引，不能混用两种会话的 schema；没有可用 ChatCut 连接时记录缺项，不虚构工程。先检查已有工程素材，导入本地文件时加载 asset-import 技能，采用其官方 helper。
2. **建立时间安排。** 导入配音，沿用分镜结束值建立镜头标记与素材区间。原文的节拍点是镜头结束标记，不是音乐自动踩点。当前工具支持与配音 item 关联的 clip marker，使用实际 itemId 和工具 schema 写入。
3. **制作 A-roll。** 完整使用包内角色参考和当前项目原图，按动作状态表生成或复用图片，状态切换对应实际旁白；每张图在时间轴独立调整。局部推近用于强调，需要其他动态方式时按当前镜头需求与授权处理。
4. **制作 B-roll。** 查看已确认的视觉参考，按飞书原文先完成静态布局，再依据[元素与动作表](broll-editable.md)制作动效。先匹配 [包内模板索引](../assets/broll/templates/index.json)，动效挑选完整调用 X 06，输入原镜头语义，并在原文之外附上[浅灰手绘规范](broll-visual-style.md)与下方调度规则。参考图限定视觉语言，不把检索资料示例的构图套到所有镜头。制作 ChatCut 原生 MG 时加载当前 create-motion-graphics 技能；外部工具只用于所需的独立素材，不替代整片可编辑时间轴。
5. **加入字幕与声音。** 按原时间轴安排字幕，并完成原文要求的声音层次。已有合适素材优先复用，生成音效或 BGM 前核实实际调用是否消耗 ChatCut 积分。
6. **检查后交付。** 按原文检查并修正受影响镜头，返回可编辑工程、镜头制作清单和分类待返工清单。模板名与来源记录实际使用结果，不把候选链接写成已使用。字幕、源备份和文件验收同时执行 [字幕与交付检查](captions-and-delivery.md)；声音步骤按 [声音后期](audio-postproduction.md)。

### 毫秒与帧的接口

ChatCut 的时间轴素材和标记以帧定位。读取实际帧率后，将原毫秒切点一次映射为共享帧边界表，标记与相邻镜头都使用这同一份结果，避免每镜单独取整产生空隙或重叠。保留原毫秒值，并报告发生的帧量化误差；不要把帧精度声称成任意毫秒值均可零误差实现。

末镜覆盖实际配音需要的全部帧，不用裁掉配音尾部来凑帧数。字幕仍依据自己的声学时间轴，不以镜头节拍点代替字幕切分。

## 连续执行与额度

维护流程、选择风格与正式整片制作是不同任务。请求接入流程时只维护定义；整片制作获得授权后，按照原文连续完成可执行的工作，用户已经明确的选择无需重复确认。

X 06 与 ChatCut 2.0 的确认范围按当次任务调度：单独请求挑某镜动效时，展示具体方案供选择后再实现；用户明确授权连续完成样片或整片时，在该范围内沿用已确认视觉，执行者选择具体动效并记入清单，不逐镜重问。此为用户定制覆盖项，必须作为独立输入附在原文之外。静态风格确认不等于所有模板已被用户确认；未由用户逐一选择的方案写为“本次制作选择”。

原文的“始终使用 Codex 额度”是用户的计费限制，不能据此断言插件生成、预览或导出天然免费。若操作需要 ChatCut 积分，必须先取得用户确认；计费不清楚时先核实，不通过一次试调用消耗积分。确实不可替代的真实素材缺失时，指出具体镜头及所缺内容，继续不受影响的部分。

## 验证与交付范围

先读取实际时间轴结构，再用 `preview_timeline` 的 viewer 视图检查合成后的画面；仅有素材或导入成功不等于镜头已放好。检查字幕遮挡、前后衔接、画面覆盖与实际角色表现。需要判断动态时查看边界相邻帧；抽帧检查不冒充连续观看，声音平衡也不能从静态图推断。

交付可编辑 ChatCut 工程链接及原文要求的两份清单，按[项目交接](timing-and-handoff.md)保存续做记录与本地素材。原文要求的本地工程文件须另行核实实际导出格式和保留能力；若尚未取得，明确列为未完成，不能把链接等同本地工程包。不要用一个整片扁平 MP4 代替可编辑工程。

用户要求最终 MP4、渲染或下载时，再加载 export 技能，使用当前 `submit_export` / `track_export` 流程。完成后交付真实下载链接；队列状态或预览图不代表成片已经导出。
