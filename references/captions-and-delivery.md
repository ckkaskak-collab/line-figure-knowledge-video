# 字幕、备份与成片检查

字幕显示文字来自定稿，真实发声时间来自声学结果。保留原始识别；识别错字可以在复核副本中纠正，实际漏读或误读要处理音频。

## 字幕切分与显示

本规则是本工作流的默认字幕样式；用户另有明确要求时按本次要求执行。

1. **先按标点换屏，再去掉显示标点。** 原稿中的逗号、顿号、句号、问号、感叹号、分号、冒号及英文对应标点作为字幕切换点。连续标点视为一个边界，引号、括号等配对标点不单独生成空卡。这里的换屏是切换字幕 Card，画面分镜仍按内容与动作设计，不要求每个标点更换 B-roll。
2. **每屏严格一行。** 不插入换行，也不依赖自动折行。按最终字体、字号和可用宽度检查；过长时，在完整分句或词组边界继续拆成先后两屏。不得按固定字数截断名词短语、把“的软件”等句尾挂到下一屏，或把不同分句的尾首拼在同一屏。保留清晰可读的字号。
3. **去掉的是显示标点。** 定稿、原始 ASR 和声学短语表保留原貌；最终 Card 与交付 SRT 使用去标点后的文字。保留字词、顺序、大小写和含义，小数点、正负号、百分号、版本号、网址及代码中的必要符号不作为普通句读删除或拆开。
4. **切分时间来自真实配音。** 先保存带原文标点的字幕分组，按真实词级时间对齐，再生成无标点的显示文字。字幕分组与分镜声学表分开保存；仅调整字幕时保留已确认配音与镜头时间。若切点落在一个 ASR 词内部，复核该处发声边界，不按字数估时。为阅读延长显示时不覆盖下一条真实发声，不为凑时长跨标点合并。

例如原稿“又没有必须用 Windows 的软件，我会优先考虑 Mac。”分为两屏：“又没有必须用 Windows 的软件” → “我会优先考虑 Mac”。“M 系列芯片、16GB 内存、512GB 硬盘”依次显示三屏，各占一行。

## 最终字幕与 SRT

1. 保存带标点的原文分组，以及最终 Card 的显示文字、帧区间、工程帧率与样式。分别核对原文完整覆盖、字词与有意义符号保真，以及显示标点已移除；不宣称显示文本与原稿逐字完全相同。
2. 用目标工程的合成画面检查每屏一行、宽度、底部安全距离和对主体的遮挡。Remotion 可设置 `whiteSpace: 'nowrap'`，但仍须检查真实渲染宽度；不能用裁切或省略号隐藏溢出。重点抽查最长字幕、英文/数字混排，以及标点前后相邻两屏。
3. 原生导出的 SRT 应与最终 Card 的无标点显示文字和时间一致。若不同，保留原件作诊断，把最终 Card 规范化为下述格式，再执行 `scripts/captions_to_srt.py`。该脚本忠实导出传入的 Card，不负责语义切分、删除标点或生成发声时间；不使用仍带原文标点的声学 SRT 代替交付字幕。
4. 按实际播放核对字幕出现、消失和停顿。为阅读延长显示是独立的布局决定，不修改真实发声记录。

```json
{
  "fps": "30",
  "cards": [
    {"text": "先查资料", "start_frame": 6, "end_frame": 30},
    {"text": "再回答", "start_frame": 39, "end_frame": 66}
  ]
}
```

以上帧数仅作格式示例，不是音频证据。`end_frame` 为不包含的右边界。宿主 Card schema 可能变化，由助手按实际返回字段转换，不能假设任意原始快照都可直接输入脚本。

## 可继续制作的备份

记录定稿、音频、声学表、连续表、分镜、素材、项目/时间轴/资产/片段 ID。MG 需要同时保存代码、属性定义和时间轴实例的 Effective Props；资产默认值不能代替最终实例设置。真实截图、字幕和声音轨保留独立映射。

逐项记录素材已下载的文件路径和哈希。只有云端 asset ID 而没有音频或图像文件时，将其列为未取得的本地素材。代码快照依赖原生运行时，不称为通用剪辑软件能直接打开的工程。

修改配乐或重新导出后，在 `project-state.json` 指向当前交付版本；旧 ZIP 和旧清单继续保持其版本属性，不作为最新结果引用。

## 导出后检查

正式成片导出前先核对声音阶段：旁白、BGM、必要音效、首尾淡变及人声避让。项目记录为“配乐/音效待做”时，不能仅因画面已确认就跳过；按 [声音后期](audio-postproduction.md) 完成已授权部分。纯旁白审阅版应明确命名，避免被误当作完整声音版本。

- 布局修订后核对实际合成画面：弧线风格保持一致、各尖端不重叠、文字处在指向位置、同组短句间距紧凑。检查箭头入场及完整呈现时的帧，不以修改代码成功代替视觉核对。
- 具体平台核验真实标识；多平台连线不穿字、不共用拥挤落点；股价图检查绘制过程、最终状态及真实数据/走势示意的区分。B-roll 讲解头像按[头像检查](broll-narrator.md#检查)核对完整面部、朝向、音量同步、遮挡和 A-roll 隐藏。
- 按 [画面来源规则](broll-visual-style.md#画面中的来源与制作说明) 检查各镜头的 note 等实际显示值；来源留在本地清单，保留定稿中的事实限定。来源隐藏与文字对齐都要在编码后的 MP4 再抽帧复核。

- 使用当前宿主支持的导出流程，核对任务结果和真实下载文件。请求名为 archive 不证明拿到 ZIP；按实际文件类型判断。
- MP4 核对视频/音频流、分辨率、帧率、帧数、画面时长和容器时长。音频编码填充可能使容器稍长，说明实际差异，不裁掉旁白凑数。
- 有 FFmpeg 时执行完整解码检查，再看实际编码画面；这仍不能代替连续观看和回听。
- NLE 导出检查素材重连、MG、字幕和声音保留范围；账号套餐或导出格式的限制按本次实测记录，不把一次错误固化成永久产品规则。

交付分别列出：原生可编辑工程、源素材/代码备份、真实导出的 MP4、SRT、按需封面和确实取得的 NLE 包。结构检查、抽帧、连续观看、回听、解码各自记录范围；没有做的检查保留为未完成。
