# 字幕、备份与成片检查

字幕显示文字来自定稿，真实发声时间来自声学结果。保留原始识别；识别错字可以在复核副本中纠正，实际漏读或误读要处理音频。

## 字幕切分与显示

本规则是本工作流的默认字幕样式；用户另有明确要求时按本次要求执行。

1. **按完整语义换屏，再去掉显示标点。** 先以原稿中的逗号、顿号、句号等句读为候选边界。短词或连续列举若导致约一秒以内的频繁切换，合并为完整、读得完的语义组，例如“自由、多变、充满惊喜”可作为一屏；不机械地每个顿号换卡。连续标点视为一个边界，引号、括号不生成空卡。这里的换屏是切换字幕 Card，画面分镜仍按内容与动作设计。
2. **每屏严格一行。** 不插入换行，也不依赖自动折行。按最终字体、字号和可用宽度检查；过长时，在完整分句或词组边界继续拆成先后两屏。不得按固定字数截断名词短语、把“的软件”等句尾挂到下一屏，或把不同分句的尾首拼在同一屏。保留清晰可读的字号。
3. **去掉的是显示标点。** 定稿、原始 ASR 和声学短语表保留原貌；最终 Card 与交付 SRT 使用去标点后的文字。保留字词、顺序、大小写和含义，小数点、正负号、百分号、版本号、网址及代码中的必要符号不作为普通句读删除或拆开。
4. **真实发声与显示区间分别保存。** 带标点原文和词级时间保持原貌；字幕用真实发声起点，短停顿中保持上一条，到下一条起点直接换屏，避免先消失几帧再出现。确有较长留白或叙事需要时才安排空屏。合并限于完整短句或连续列举，不硬拼不同分句的尾首。若切点落在 ASR 词内部，复核发声边界，不按字数估时。只改字幕时保留已确认配音与镜头时间。
5. **字幕跟随配音，跨镜连续。** 整段旁白贯穿多个 B-roll 时，可用与该旁白对应的独立全片字幕轨；若每镜保留字幕实例，按显示区间与镜头区间的实际交集分配，跨镜部分在两镜接续。不得根据原文字节位置或换行，把字幕归到已经结束的镜头。单镜预览与全片使用同一最终 Card 数据。

例如原稿“又没有必须用 Windows 的软件，我会优先考虑 Mac。”可分两屏：“又没有必须用 Windows 的软件” → “我会优先考虑 Mac”。“M 系列芯片、16GB 内存、512GB 硬盘”根据真实语速、单行宽度和阅读时间决定连续换屏或语义合并。

## 字幕连续性检查

修复闪烁、漏句或跨镜中断时检查全片字幕轨：原文按顺序完整覆盖、每屏时长可读、短停顿无意外空档、相邻卡无重叠，所有跨镜句都能实际显示。统计覆盖只是数据检查；还要检查每次换屏及切镜前后的实际合成画面，并在编码后的 MP4 检查对应区域。整帧平均误差可能掩盖局部字幕缺失，须单独检查字幕字形与底板。使用逐帧图像比较时记录范围和阈值；静态最终帧与字幕条数相同不能证明播放稳定。

时间数据连续、单帧正常而批量导出仍闪烁时，检查媒体加载与实际合成路径，用同一短区间连续渲染做对照。当前宿主曾出现画布媒体与 HTML 叠层间歇丢失；在对应工程中换用受加载控制的 `Img` 和 `OffthreadVideo` 后短区间通过。按本次实测选择实现，不把换帧率、换显卡后端或只看静态预览当作修复证据。

## 最终字幕与 SRT

1. 保存带标点的原文分组，以及最终 Card 的显示文字、帧区间、工程帧率与样式。分别核对原文完整覆盖、字词与有意义符号保真，以及显示标点已移除；不宣称显示文本与原稿逐字完全相同。
2. 用目标工程的合成画面检查每屏一行、宽度、底部安全距离和对主体的遮挡。Remotion 可设置 `whiteSpace: 'nowrap'`，但仍须检查真实渲染宽度；不能用裁切或省略号隐藏溢出。重点抽查最长字幕、英文/数字混排，以及标点前后相邻两屏。
3. 原生导出的 SRT 应与最终 Card 的无标点显示文字和时间一致。若不同，保留原件作诊断，把最终 Card 规范化为下述格式，再执行 `scripts/captions_to_srt.py`。该脚本忠实导出传入的 Card，不负责语义切分、删除标点或生成发声时间；不使用仍带原文标点的声学 SRT 代替交付字幕。
4. 按实际播放核对字幕出现、消失和停顿。为阅读延长显示是独立的布局决定，不修改真实发声记录。

```json
{
  "fps": "30",
  "cards": [
    {"text": "先查资料", "start_frame": 6, "end_frame": 30},
    {"text": "再回答", "start_frame": 39, "end_frame": 66}
  ]
}
```

以上帧数仅作格式示例，不是音频证据。`end_frame` 为不包含的右边界。宿主 Card schema 可能变化，由助手按实际返回字段转换，不能假设任意原始快照都可直接输入脚本。

## 可继续制作的备份

记录定稿、音频、声学表、连续表、分镜、素材、项目/时间轴/资产/片段 ID。MG 需要同时保存代码、属性定义和时间轴实例的 Effective Props；资产默认值不能代替最终实例设置。真实截图、字幕和声音轨保留独立映射。

逐项记录素材已下载的文件路径和哈希。只有云端 asset ID 而没有音频或图像文件时，将其列为未取得的本地素材。代码快照依赖原生运行时，不称为通用剪辑软件能直接打开的工程。

修改配乐或重新导出后，在 `project-state.json` 指向当前交付版本；旧 ZIP 和旧清单继续保持其版本属性，不作为最新结果引用。

## 叙事与动作检查

按[叙事与动作设计](visual-storytelling.md)核对本次制作或修改的范围，并记录代表性镜头、检查方式和发现的问题：

- **A-roll 场景成立。** 看状态序列、换图前后帧及完整动作段，检查人物的处境、行动与结果能否读懂，视线、持物手和物件位置是否连续，结果是否停留。只有姿态替换或整图缩放时，回到动作设计修正。
- **B-roll 讲解成立。** 对机制、比较、筛选等镜头，沿口播检查图形、图片/真实素材及标注的对应关系，确认观众能追踪对象怎样变化及变化说明什么。纯清单按清晰度验收；不强加无意义的联动。
- **段落衔接成立。** 连看相邻镜头，检查 A/B 的选择是否服务本段作用，场景中的物件能否自然进入图解、图解结果能否承接后续场景，以及同类镜头是否反复使用相同动作。

画面布局、整组出现、叙事动作和口播同步分别核对。动态预览通过后，已导出的项目还应从编码后的 MP4 复核代表性动作段；仅静态抽帧时，记录为静态检查，保留节奏与连续观看的未检状态。

## 逐项出现检查

制作或修改逐项讲解画面时，按[整组随口播出现](broll-editable.md#整组随口播出现)核对所有受影响的语义组和镜头实例：

1. **锚点完整。** 每个独立讲解项都有实际口播依据，组 ID 与框线、文字、数值、底条及连线的映射一致。重点检查项目多于锚点时，是否错误复用了最后一个锚点，导致后几项仍同时跳出。
2. **出现前完整隐藏。** 查看各组入场前的实际帧，确认未来组没有露出空框、模型名称、单位、底条、勾选标记或指向未来目标的连线。
3. **中间阶段逐项成立。** 查看第一组出现后、增加第二组后等阶段，以及连线完整展开的结果；确认一组内部同步、组间顺序跟随配音，既有元素的位置稳定。最终布局图不能代替这些过程检查。
4. **检查全片同类问题。** 用户提供的截图是定位入口，检查范围还包括同类参数卡、榜单、流程、分支、价格、文档结果和代码图解，以及共用组件的其他实例。只改示例镜头不算完成同类问题修订。
5. **检查真实导出。** 导出后，从 MP4 再检查对应出现前后和逐项累积的帧，确认动态控制生效。保存组 ID、口播锚点、动作帧及检查画面的对应记录；代码修改成功、静态预览或最终状态抽帧均不能替代该检查。

仅修动效时，对照原稿、旁白文件及最终字幕 Card/SRT 的内容或哈希，确认原内容保持不变。实际完成的抽帧、连续观看和听审仍分别记录。

## 导出后检查

正式成片导出前先核对声音阶段：旁白、BGM、必要音效、首尾淡变及人声避让。项目记录为“配乐/音效待做”时，不能仅因画面已确认就跳过；按 [声音后期](audio-postproduction.md) 完成已授权部分。纯旁白审阅版应明确命名，避免被误当作完整声音版本。

- 布局修订后核对实际合成画面：弧线风格保持一致、各尖端不重叠、文字处在指向位置、同组短句间距紧凑。检查箭头入场及完整呈现时的帧，不以修改代码成功代替视觉核对。
- 具体平台核验真实标识；多平台连线不穿字、不共用拥挤落点；股价图检查绘制过程、最终状态及真实数据/走势示意的区分。B-roll 讲解头像按[头像检查](broll-narrator.md#检查)核对完整面部、朝向、音量同步、遮挡和 A-roll 隐藏。
- 按 [画面来源规则](broll-visual-style.md#画面中的来源与制作说明) 检查各镜头的 note 等实际显示值；来源留在本地清单，保留定稿中的事实限定。来源隐藏与文字对齐都要在编码后的 MP4 再抽帧复核。

- 使用当前宿主支持的导出流程，核对任务结果和真实下载文件。请求名为 archive 不证明拿到 ZIP；按实际文件类型判断。
- MP4 核对视频/音频流、分辨率、帧率、帧数、画面时长和容器时长。音频编码填充可能使容器稍长，说明实际差异，不裁掉旁白凑数。
- 有 FFmpeg 时执行完整解码检查，再看实际编码画面；这仍不能代替连续观看和回听。
- NLE 导出检查素材重连、MG、字幕和声音保留范围；账号套餐或导出格式的限制按本次实测记录，不把一次错误固化成永久产品规则。

交付分别列出：原生可编辑工程、源素材/代码备份、真实导出的 MP4、SRT、按需封面和确实取得的 NLE 包。结构检查、抽帧、连续观看、回听、解码各自记录范围；没有做的检查保留为未完成。
