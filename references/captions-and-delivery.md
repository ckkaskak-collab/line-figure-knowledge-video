# 字幕、备份与成片检查

字幕显示文字来自定稿，真实发声时间来自声学结果。保留原始识别；识别错字可以在复核副本中纠正，实际漏读或误读要处理音频。

## 最终字幕与 SRT

1. 保存最终 Card 的文字、帧区间、工程帧率与样式。字词匹配检查和标点/大小写检查分开，不能以去掉标点后的相等宣称显示文本完全相同。
2. 用目标工程的合成画面检查换行、底部安全距离和对主体的遮挡。工具报告的行数或溢出状态仅作辅助。含英文、数字或字体回退的字幕尤其需要复看。
3. 将原生导出的 SRT 与最终 Card 核对。若丢失标点或文字不同，保留原件作诊断，把最终 Card 规范化为下述格式，再执行 `scripts/captions_to_srt.py` 生成校正版。
4. 按实际播放核对字幕出现、消失和停顿。为阅读延长显示是独立的布局决定，不修改真实发声记录。

```json
{
  "fps": "30",
  "cards": [
    {"text": "先把问题说清楚。", "start_frame": 6, "end_frame": 72}
  ]
}
```

`end_frame` 为不包含的右边界。宿主 Card schema 可能变化，由助手按实际返回字段转换，不能假设任意原始快照都可直接输入脚本。

## 可继续制作的备份

记录定稿、音频、声学表、连续表、分镜、素材、项目/时间轴/资产/片段 ID。MG 需要同时保存代码、属性定义和时间轴实例的 Effective Props；资产默认值不能代替最终实例设置。真实截图、字幕和声音轨保留独立映射。

逐项记录素材已下载的文件路径和哈希。只有云端 asset ID 而没有音频或图像文件时，将其列为未取得的本地素材。代码快照依赖原生运行时，不称为通用剪辑软件能直接打开的工程。

修改配乐或重新导出后，在 `project-state.json` 指向当前交付版本；旧 ZIP 和旧清单继续保持其版本属性，不作为最新结果引用。

## 导出后检查

正式成片导出前先核对声音阶段：旁白、BGM、必要音效、首尾淡变及人声避让。项目记录为“配乐/音效待做”时，不能仅因画面已确认就跳过；按 [声音后期](audio-postproduction.md) 完成已授权部分。纯旁白审阅版应明确命名，避免被误当作完整声音版本。

- 布局修订后核对实际合成画面：弧线风格保持一致、各尖端不重叠、文字处在指向位置、同组短句间距紧凑。检查箭头入场及完整呈现时的帧，不以修改代码成功代替视觉核对。
- 具体平台核验真实标识；多平台连线不穿字、不共用拥挤落点；股价图检查绘制过程、最终状态及真实数据/走势示意的区分。B-roll 讲解头像按[头像检查](broll-narrator.md#检查)核对完整面部、朝向、音量同步、遮挡和 A-roll 隐藏。
- 按 [画面来源规则](broll-visual-style.md#画面中的来源与制作说明) 检查各镜头的 note 等实际显示值；来源留在本地清单，保留定稿中的事实限定。来源隐藏与文字对齐都要在编码后的 MP4 再抽帧复核。

- 使用当前宿主支持的导出流程，核对任务结果和真实下载文件。请求名为 archive 不证明拿到 ZIP；按实际文件类型判断。
- MP4 核对视频/音频流、分辨率、帧率、帧数、画面时长和容器时长。音频编码填充可能使容器稍长，说明实际差异，不裁掉旁白凑数。
- 有 FFmpeg 时执行完整解码检查，再看实际编码画面；这仍不能代替连续观看和回听。
- NLE 导出检查素材重连、MG、字幕和声音保留范围；账号套餐或导出格式的限制按本次实测记录，不把一次错误固化成永久产品规则。

交付分别列出：原生可编辑工程、源素材/代码备份、真实导出的 MP4、SRT、按需封面和确实取得的 NLE 包。结构检查、抽帧、连续观看、回听、解码各自记录范围；没有做的检查保留为未完成。
